# ACNH 3.0.1 optional DLC review

AI-assisted self-review by Codex on 2026-10-29; no independent reviewer was used.
Request, build commands and actual validation results are in the
[work log](../work-logs/2026-10-29-acnh-dlc.md).

## Scope

- Separate owner-supplied NSP preparation, pinned package/RomFS identities and
  AddOnContent CNMT application/version checks.
- Optional generated runtime configuration, DLC enumeration, read-only image
  mounts, bounded file ranges, directory enumeration and unmount behavior.
- Host/manifest identity binding, packaging receipts and launcher resource paths.
- Preservation of the no-DLC build and the existing base/update integrity checks.

## Findings and disposition

- Corrected cross-backend mount-name collision checks. Host-storage and DLC
  registration use the host mount lock when checking/registering names, with a
  consistent host-lock then DLC-lock order. RomFS also rejects a name already
  held by a DLC mount.
- Confirmed that DLC offsets are regenerated from the pinned, rehashed images,
  rather than trusted from an editable preparation index. Per-file reads clamp
  to the file range and use read-only descriptors; write/resize paths reject
  those handles. Traversal and missing content are rejected.
- Confirmed that a runtime compiled without DLC cannot be packaged with DLC
  data, or vice versa: its embedded manifest identity must match host inputs.
- Moved input verification ahead of deletion of an existing output bundle.
- The actual packaged FS probe exposed a stale, nonexistent audio sample path
  in the pre-existing diagnostic. Replaced the fixture with an audio stream
  selected from the verified ACNH index; retained the byte comparisons and
  repeated-root-separator/traversal checks.
- Confirmed that game inputs and generated headers/images remain ignored local
  artifacts, and all new implementation and tests are under `games/acnh/`.

No remaining blocking issue was identified in this review. Runtime unit tests
and a Clang static analysis of `runtime/dlc.c` passed; see the work log for final
package checks and their limits. The probes do not verify Happy Home Paradise
progression, reward delivery, DLC audio/movie playback or complete 3.0.1 gameplay.
