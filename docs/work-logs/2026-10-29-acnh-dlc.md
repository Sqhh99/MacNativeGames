## Changes

- Added `tools/prepare_dlc.py` for the exact three separate packages, rejecting
  unknown, duplicate, mixed-title or incomplete inputs. Existing base/update
  preparation remains reusable.
- Added optional `build_host.py --dlc` support with remembered work-local paths,
  generated file ranges from rehashed images, and a compiled manifest identity.
- Implemented actual add-on enumeration, cache queries, mounts/unmounts,
  read-only file slices, file types and directory listings. Image hashes are
  verified on initialization, mutation metadata is checked when opening files,
  and file reads clamp to the requested file's range.
- Added packaging validation for the runtime's DLC identity, all three bundled
  images, the manifest and explicit DLC receipt entries. Input verification now
  precedes deletion of an existing output App. The launcher sets the bundled DLC
  directory, independently of the current working directory.
- Added a `probe-dlc` mode using the guest-facing AOC/FS symbol maps, synthetic
  runtime/asset regressions, and a packaging mismatch regression. Documented the
  reproducible preparation/build/probe flow in `games/acnh/README.md`.
- Final-package validation also exposed a pre-existing FS probe fixture that
  named a nonexistent audio stream. The diagnostic now selects an actual
  `.bwav` stream from the verified ACNH index and preserves its byte, normalized
  path and traversal assertions. The initial failure is retained in
  `work/dlc-validation/before-audio-probe-fix-probe-fs.log`; it followed a
  successful full base/update RomFS hash and preceded the final corrected build.
- Preserved the owner's settings panel, shared inputs, saves, existing optional
  FPS configuration and shader cache/seed. No new cheats or mods were enabled.

## Build and validation

Reused the verified base 1.0.0 plus update 3.0.1 preparation, work-local Python
environment, tools, graphics objects and shader seed (6,470 shaders). Built with
`MACOSX_DEPLOYMENT_TARGET=27.0`:

```sh
build/acnh-3.0.1/work/venv/bin/python -B games/acnh/build_host.py \
  --prepared build/acnh-3.0.1/work/prepared \
  --work build/acnh-3.0.1/work/native --shared-fonts game-assets/shared/fonts \
  --dlc build/acnh-3.0.1/work/dlc
build/acnh-3.0.1/work/venv/bin/python -B games/acnh/scripts/package_native_app.py \
  --prepared build/acnh-3.0.1/work/prepared --work build/acnh-3.0.1/work/native \
  --shared-fonts game-assets/shared/fonts \
  --output "build/acnh-3.0.1/Animal Crossing New Horizons.app"
```

## Limitations and retained local work

The 3.0.1 port and DLC support remain experimental. No complete gameplay test,
Happy Home Paradise progression, promotional reward delivery, DLC audio/movie
playback, or 1.2.1 full application rebuild was performed. The no-DLC runtime
configuration was tested with synthetic data. Package/probe success must not be
reported as verification of these gameplay paths.

New game packages, prepared images, generated headers, executable output, fonts,
keys, caches and saves remain ignored local data. Nothing was staged or committed
at initial delivery; the subsequent commit authorization is recorded below.
The pre-existing untracked logs for merging main/building DMGs, cheat assets and
removing installed Zelda games were left untouched. A read-only `ps` inventory
attempt was denied by the sandbox and was not needed for the build; no running
game process was stopped. Launch Services registration can emit its existing
nonfatal Spotlight scan error inside the sandbox; package validation is recorded
separately from Finder registration.
